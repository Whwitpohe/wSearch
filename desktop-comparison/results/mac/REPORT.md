## 实测结果

独立启动应用两次。每次用 Control+Option+Shift+S 触发并交替执行四次正反向拖框，共 **8 次有效常规拖框**。首次成功截图单列，后续列为另外 7 次的中位数。

| 计时段 | 首次（ms） | 后续中位数（ms） |
| --- | ---: | ---: |
| 热键到覆盖层可见 | 295.0 | 267.5 |
| 热键到可见拖框 | 346.1 | 307.4 |
| 鼠标松手到 PNG 可读取 | 20.9 | 14.9 |

正向从 (400, 330) 拖到 (600, 450) 逻辑点，反向交换两端。期望和实测 PNG 均为 **400 × 240 px**，左上角为 (800, 660)，右下角半开边界为 (1200, 900)。8 个常规 PNG 的 96,000 个像素分别与同一参考裁剪逐像素一致。冻结帧试次在覆盖层可见后更新合成图案，覆盖层消失后看到了新图案，剪贴板 PNG 与更新前的参考裁剪逐像素一致。Esc 关闭了覆盖层，剪贴板未变化。两轮各自保存在内存的剪贴板条目与格式均还原并核对。

8 个有效常规试次的进程组采样峰值为 132.60–189.44 MiB。全部截图试次中的最高采样值为 **189.45 MiB**，出现在冻结帧试次。截图峰值包含 Tauri 宿主和 `wsearch-capture`。打开说明页时计入归属于 Tauri 的 WebContent、GPU、Networking 三个 WebKit 进程。关闭后 WebContent 已退出，GPU 和 Networking 在采样窗口内仍在。使用 `proc_pid_rusage` 的 physical footprint，Windows 私有工作集另见 Windows 报告。

arm64 release 构建使用 Xcode 27.2（27B52）、Apple Swift 6.4.2、rustc/cargo 1.100.0 和 Tauri 2.12.7。压缩包 2,286,183 字节（2.18 MiB），解压后应用包四个常规文件合计 6,708,796 字节（6.40 MiB）。解压后复验 ad hoc 签名通过。压缩包 SHA-256 为 `915fb743b6f5969a47c72182da86a2eb9be0987cb0e66605597ce39f8d361600`。

## 复现和测量口径

1. 在待测提交的 `desktop-comparison` 目录执行 `awk 'index($0, "(cd electrobun-host ") == 1 { exit } { print }' build-unix.sh | bash`，运行构建脚本的 Tauri 阶段。用 `open` 启动生成的 `wSearch Tauri Trial.app`，在「屏幕与系统音频录制」为该应用授权。
2. 用无边框合成窗口覆盖内建显示器。底色为 sRGB (0.24, 0.58, 0.76)。用 9 × 7 逻辑点的格子填色。格子的左上角从 (380, 310) 开始，按宽和高递增，终止条件为 x < 624、y < 472。每个格子以左上角坐标计算 `s = ((x * 73) ^ (y * 139)) & 255`，RGB 为 `(55 + s % 125, 60 + (s * 5) % 120, 65 + (s * 7) % 118)`。参考图和剪贴板 PNG 转为 sRGB 后对比。冻结帧试次在覆盖层出现后把底色换为 (0.77, 0.24, 0.63)，把格子红色项中的 `s` 换为 `s + 87`，其余颜色项不变。
3. 用同一单调时钟记录键鼠事件发出、ScreenCaptureKit 完整帧回调中第一次出现覆盖层提示和拖框边线、剪贴板首次读到 PNG。录屏流请求的最小帧间隔为 8.33 ms，实际观测还受显示刷新与回调调度约束。可见拖框耗时包含自动化在覆盖层出现后按下鼠标、约 10 ms 后发送拖动的时间。松手到 PNG 的检测约每 2 ms 轮询。冻结帧包含人为设置的底图更新时间，单列在逐次数据中。
4. 托盘和说明页每个状态取 7 个样本。说明页用应用自带 `WSEARCH_TRIAL_SHOW_UI=1` 启动，打开和关闭后各等待 2 秒再采样。截图进程组约每 20 ms 采样，最高值为样本峰值。WebKit 进程按系统 responsible PID 归组。

首次授权检查和 14:36 的复测中，热键均成功启动辅助进程，进程因 TCC 拒绝录屏以 2 退出。为应用授权后重新启动，14:38 完成上述测量。授权失败试次在 JSON 中单列。按最新范围，Electrobun 和双版本 A/B/B/A 未测。未检测到外接屏，混合缩放和非零屏幕原点未测。
