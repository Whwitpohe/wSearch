# Windows Tauri 截图窗口预热实测

Tauri 托盘主进程现在在自己的 UI 线程预先创建一个隐藏的 Win32 选区窗口。常驻资源包括一个 1×1 初始窗口和一张 250×42 像素的提示位图。按快捷键后按光标所在显示器取屏，使用物理像素定位窗口；只在截图期间注册 Esc，复制或取消后隐藏窗口并释放整屏位图。macOS 和 Linux 继续使用各自的原生取屏组件。

## 同机对照

Windows x64，主屏 2560×1440、100% 缩放，副屏 2560×1600、150% 缩放。顺序为旧、新、新、旧，每版两次独立启动，共 12 次有效框选。两版均用系统全局快捷键 Ctrl+Alt+Shift+S。桌面采样确认截屏提示可见、拖框起点已命中正确的窗口。在这组对照中将鼠标消息定向发送到命中的原生窗口，再核对桌面选区像素和剪贴板。另行使用 Windows 鼠标输入进行验证。

| 指标（中位数） | 旧版，按次创建 | 预热版 |
|---|---:|---:|
| 热键到可拖框 | 170.4 ms | **57.1 ms** |
| 热键到桌面出现拖框边线 | 183.4 ms | **70.8 ms** |
| 取屏 | 32.1 ms | 32.1 ms |
| 取屏完成至首次程序内绘制完成 | 115.8 ms | **5.8 ms** |
| 刚启动只挂托盘，私有工作集 | 约 1.70 MiB | **1.79 MiB** |
| 截图后回托盘，私有工作集 | 约 1.77 MiB | **约 1.82 MiB** |
| 截图进程树峰值私有工作集 | 18.63 MiB | **16.79 MiB** |

预热版 12 次就绪时间为 **50.8–67.1 ms**；旧版为 **155.1–196.9 ms**。两次进程会话中每次 6 张截图都复用了同一原生窗口。独立核对也确认了按键前的隐藏窗口、重复快捷键保持同一次选区、取消后的窗口隐藏和剪贴板保留。双屏正反向裁剪的结果与冻结原帧逐像素一致。

工作集与提交量采用不同口径。另一次独立采样中，旧 / 新托盘私有工作集为 **1.699 / 1.781 MiB**，含共享页的进程工作集为 **14.82 / 15.65 MiB**，私有提交量为 **2.316 / 2.527 MiB**。这些数字是进程内存，专用显存和 DWM 自己的表面单独核算。

## 与当前 Electron 安装版对照

预热版另做了 6 次真实 Windows 鼠标拖动并读回剪贴板。主屏 3 次就绪中位数 **60.0 ms**，副屏 3 次 **64.6 ms**。相同主屏、相同合成背景下，当前 Electron 安装版使用自己的 Ctrl+Alt+S，6 次实际鼠标拖动的就绪中位数 **97.0 ms**，选框像素出现为 **199.6 ms**。此前完整 Electron 测量的就绪中位数为 **141.8 ms**。完整产品还提供自动吸附、标注和翻译；本轮比较的交互是手动框选。

试跑时出现远程桌面抢焦点和一次副屏拖动坐标相差 1 像素；这些未通过像素或窗口检查的轮次未纳入统计。正式轮次都使用可验证的本地测试画面。测试后的剪贴板检查未发现该次异常 DIB，当时的恢复状态未能追溯确认。

## 复测

在有权限的交互式 Windows 桌面中运行。测试使用合成画面并保留可恢复的剪贴板，测试期间请暂时停止使用鼠标。用两个独立目录中的 exe 分别执行下面的命令，反向再跑一轮。加 `--physical-drag` 可使用系统鼠标输入，加 `--primary-only` 可只测主屏。

```powershell
python -X utf8 bench/tauri_warm_bench.py <原型exe路径> results/<本轮名称>.json
```
